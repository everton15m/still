# Research and decisions

Checked 12 October 2026, before implementation. Apple's [Xcode matrix](https://developer.apple.com/xcode/system-requirements) was consulted rather than assuming a latest release. It lists Xcode 27 and newer prerelease rows; this workspace reports Xcode 26.6, Swift 6.3.3, and macOS 27.0.1. The native build uses the installed Xcode macOS 26.5 SDK. Deployment is macOS 14, providing modern SwiftUI controls and the supported login service without requiring the newest OS.

## Existing approaches

| Tool | Useful approach | Scope or limitation for this project |
| --- | --- | --- |
| [GrandPerspective](https://grandperspectiv.sourceforge.net/) | Small native treemap utility; [logical versus physical sizes](https://grandperspectiv.sourceforge.net/HelpDocumentation/FileSizes.html), [hard-link handling](https://grandperspectiv.sourceforge.net/HelpDocumentation/HardLinks.html), and [metadata-only cloud scanning](https://grandperspectiv.sourceforge.net/HelpDocumentation/HowToScanCloudStorage.html) are directly relevant. | Visualization is the central workflow; Still pairs a simpler one-level folder map with short cleanup suggestions and capacity alerts. |
| [QDirStat](https://github.com/shundhammer/qdirstat) | Open-source tree, treemap, file categories, and size-first navigation; Qt implementation with configurable cleanup commands. | Qt and arbitrary commands would add dependencies and widen the safety surface. Still uses native controls and only Trash. |
| [Pearcleaner](https://github.com/alienator88/Pearcleaner) | Swift app-oriented cleanup with a separate helper and sentinel. | Much broader uninstallation and maintenance scope; its current source-available Commons Clause license is not a plain open-source license. No code is copied. Still is independently implemented under MIT without a helper. |
| [Mole](https://github.com/tw93/mole) | Open-source CLI disk analysis and explicit review-oriented cleanup. | Its optimization, live hardware monitoring, and broad maintenance are outside this request. |
| [OmniDiskSweeper](https://www.omnigroup.com/more) | Simple largest-first folder exploration and Trash. | Useful UX reference, not used as open-source implementation material. |

## Apple APIs and filesystem behavior

- [Foundation directory enumeration](https://developer.apple.com/documentation/foundation/filemanager/directoryenumerator) supplies streaming traversal. Darwin `lstat` adds inode/device identity, allocated blocks, ownership, flags, and nanosecond timestamps without following symlinks. Directory totals aggregate once in postorder. Metadata retention is bounded; progress updates arrive at most twice a second.
- [Volume capacity](https://developer.apple.com/documentation/foundation/urlresourcekey/volumeavailablecapacityforimportantusagekey) is read separately from inspection totals. Conservative available bytes drive alerts; important-usage capacity is labeled separately.
- Apple's [APFS explanation](https://developer.apple.com/documentation/foundation/about-apple-file-system) describes clones, snapshots, sparse files, and shared container space. Allocated blocks are a useful estimate but shared extents prevent exact reclaim forecasts. No attempt is made to delete snapshots or treat all purgeable bytes as freely available.
- Apple's [macOS file privacy model](https://support.apple.com/en-gb/guide/security/secddd1d86a6/web) requires consent for protected locations. [App Sandbox](https://developer.apple.com/documentation/security/app-sandbox) would constrain arbitrary startup inspection; this locally distributed utility is unsandboxed, unprivileged, and respects TCC and SIP. Coverage gaps are visible. No Full Disk Access entitlement exists.
- [Trash](https://developer.apple.com/documentation/foundation/filemanager/trashitem(at:resultingitemurl:)) is the sole removal operation. [File coordination](https://developer.apple.com/documentation/foundation/nsfilecoordinator) coordinates each move with cooperating file presenters. A complete read-only snapshot is reviewed and revalidated before moving; there is no permanent-delete fallback.
- [CryptoKit SHA-256](https://developer.apple.com/documentation/cryptokit/sha256) verifies equal-sized candidates using 1 MB read chunks. Open flags reject replaced symlinks and special files; timestamps and identities are checked before, during, and after comparison. Hard-link aliases and dataless placeholders are omitted. Cloud-managed Library locations are inspection-only.
- [UserNotifications](https://developer.apple.com/documentation/usernotifications/scheduling-a-notification-locally-from-your-app) provides native alerts with a foreground dashboard action. Persistent episode state and recovery hysteresis prevent repeated warnings. A tolerant five-minute timer only reads capacity.
- [SMAppService.mainApp](https://developer.apple.com/documentation/servicemanagement/smappservice/mainapp) registers the optional main app at login. It keeps implementation small: no launch daemon, background helper, admin prompts, or repeated full scans. Monitoring requires the main app to remain running.

This is a reliability-first inference from the sources: a bounded scanner, one-level proportional treemap, direct Finder actions, explicit Trash review, and a single main-app monitor meet the requested scope without copying another tool or introducing third-party dependencies.
